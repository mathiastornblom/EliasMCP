## Buggar funna och fixade

### Bug 1: Testcontainer existerade inte — 8/16 tester gav 404
- **Fil**: `tests/integration.ts`
- **Symptom**: Alla container-scoped tester misslyckades med HTTP 404
- **Root cause**: `mcp-test`-containern existerade inte på ELIAS-servern
- **Fix**: Lade till `--- Test Container Setup ---`-fas som skapar containern om den saknas och `--- Test Container Teardown ---` som tar bort den om vi skapade den. `containerCreatedByTest`-flagga styr teardown.

---

### Bug 2: `ReferenceError: containerCreatedByTest is not defined`
- **Fil**: `tests/integration.ts`
- **Symptom**: Crash vid teardown-fasen efter container-skapande
- **Root cause**: `containerCreatedByTest` deklarerades inuti första `if (TEST_CONTAINER)`-blocket men refererades i ett andra sådant block längre ner
- **Fix**: Flyttade `let containerCreatedByTest = false` till modulnivå (rad 69)

---

### Bug 3: HTTP 404 för alla container-scoped routes trots att containern existerade
- **Fil**: `src/client.ts`
- **Symptom**: `list images`, `list templates`, `list EPMs` m.fl. gav 404. Auth och `/containers` fungerade.
- **Root cause**: `ELIAS_BASE_URL` satt till `https://host/elias/api` men client lade till ytterligare `/api`-prefix. URL blev `.../elias/api/api/mcp-test/idfs` → 404. Auth-routes fungerade p.g.a. serverrouting-tolerans.
- **Fix**: Tog bort `/api`-prefix i all URL-konstruktion i `client.ts`. `login()` → `${this.baseUrl}/authenticate`; alla `doRequest*` → `${this.baseUrl}${path}`. Uppdaterade `.env.example` så att `ELIAS_BASE_URL` explicit inkluderar `/api` i exemplet.

---

### Bug 4: `Idf validation failed: id: Path id is required`
- **Fil**: `tests/integration.ts`
- **Symptom**: Create image-testet gav 400 Bad Request
- **Root cause**: ELIAS kräver att `id`-fältet är explicit satt i IDF-body (OpenAPI: `required: ["id","name","version","container"]`). Testet saknade `id`.
- **Fix**: Lade till `id: 'mcp-test-image'` i `testIdf`-objektet.

---

### Bug 5: `Expected name=mcp-test-image, got undefined` + DELETE 404
- **Fil**: `tests/integration.ts`
- **Symptom**: Create returnerade IDF-objekt där `id` och `name` var `null`. Efterföljande GET och DELETE använde `null` i URL → 404.
- **Root cause**: ELIAS-servern returnerar IDF med `id: null, name: null` (MongoDB-schema). Det faktiska identifieraren i URL:er är `_id` (MongoDB ObjectId).
- **Fix**: Ändrade `createdImageName` till `(data._id ?? data.id ?? data.name)`. Lade till `overwrite: true` för att hantera kvarliggande testartefakter.

---

## Serverdokumentation — avvikelse från OpenAPI-spec

**OBS:** ELIAS-servern returnerar IDF-fält som saknas i `openapi.json`:

| Fält | Typ | Notering |
|------|-----|----------|
| `_id` | string (ObjectId) | MongoDB-primärnyckel — används i GET/DELETE URL:er |
| `locked` | boolean | Om bilden är låst mot ändringar |
| `usedContainer` | string | Vilken container bilden tillhör |
| `fpmGroups` | array | FPM-grupperingar |
| `__v` | number | MongoDB versionsfält |

Detta är **inte blockerande** — OpenAPI-specen är ofullständig men implementationen fungerar korrekt med `_id` som identifierare.
